# 发布与下载

本项目的源码与安装包同时托管在 **GitHub** 与 **Gitee** 两个平台，两边内容保持同步。
国内访问 Gitee 更稳定，海外或需要 GitHub Actions 自动化构建时用 GitHub。

---

## 一、获取地址

| 平台 | 源码仓库 | 安装包下载（Releases） |
| --- | --- | --- |
| **GitHub** | <https://github.com/2405646728/school-erp> | <https://github.com/2405646728/school-erp/releases> |
| **Gitee** | <https://gitee.com/zhuliu1513/school-erp> | <https://gitee.com/zhuliu1513/school-erp/releases> |

两边都提供两种下载形式：

| 文件 | 说明 | 适用场景 |
| --- | --- | --- |
| `school-erp-<版本>-setup.exe` | Windows 安装程序，向导式安装，可选桌面快捷方式，带卸载项 | 需要装到固定目录、要开始菜单入口的场景 |
| `school-erp-<版本>-win-x64.zip` | 免安装绿色包，解压双击 `启动服务.bat` | 绿色部署、U 盘携带、不想写注册表的场景 |

> 两种包都**内置 Node 运行时**，目标电脑无需安装 Node.js、数据库或任何依赖。
> macOS / Linux 用户请下载源码后执行 `./scripts/deploy.sh` 流程（见 README「部署」章节）。

### 快速开始（下载安装包后）

1. 下载并解压 / 安装
2. 启动服务（安装版双击桌面快捷方式，绿色版双击 `启动服务.bat`）
3. 浏览器自动打开，默认地址：
   - 学校官网 `http://localhost:8000/`
   - 管理后台 `http://localhost:8000/admin`
   - 接口索引 `http://localhost:8000/api`
4. 管理员账号 `admin` / `admin123`

```bash

pnpm install
pnpm db:reset      # 初始化数据库与演示数据

```

## 三、如何发布新版本

### 3.1 本地构建产物

```bash
pnpm build         # 构建三个包
pnpm package       # 生成免安装绿色包 → release/school-erp-<版本>-win-x64.zip
pnpm installer     # 生成 Windows 安装程序 → release/school-erp-<版本>-setup.exe
```

安装程序的编译会自动获取 NSIS 编译器（首次运行联网下载约 2.4 MB，之后走本地缓存）。

### 3.2 推送源码到两个平台

```bash
git add -A
git commit -m "feat: 描述本次改动"

git push origin main    # GitHub
git push gitee  main    # Gitee
```

> 两个远程（`origin` = GitHub，`gitee` = Gitee）已在本地仓库配置好。
> 凭据由 Windows 凭据管理器保存，首次推送若提示登录，输入一次账号令牌即可。

### 3.3 发布安装包

**方式一：自动（GitHub Actions）**

打标签并推送即可触发 CI 构建并把产物自动附加到 Release：

```bash
git tag v0.1.0
git push origin v0.1.0
```

工作流 `.github/workflows/ci.yml` 会先跑类型检查、构建与 69 项接口冒烟测试，
通过后在 Windows 环境构建 zip 与 exe，上传为 Artifact 并附加到对应 Release。

**方式二：手动（Gitee 或不想用 CI 时）**

1. 在平台上进入仓库 → 「发行版 / Releases」→ 新建发行版
2. 填写版本号（如 `v0.1.0`）与更新说明
3. 把 `release/` 下的 `.zip` 与 `.exe` 拖入附件区上传
4. 发布

Gitee 若提示「附件大小超限」，可分两个发行版分别上传，或把产物放到仓库的「附件管理」中。

### 3.4 版本号位置

改版本号需要同时更新这三处（保持三处一致，README 与安装包名称都会跟着变）：

| 文件 | 字段 |
| --- | --- |
| `package.json` | `version` |
| `server/package.json` | `version` |
| `web/package.json` / `site/package.json` | `version` |

## 五、常见问题

**Q：下载的 zip 解压后双击 `启动服务.bat` 一闪而过？**
多是端口 8000 被占用。用记事本打开同目录 `.env`，把 `PORT=8000` 改成 8080 后重试；
脚本也会在窗口中给出明确提示。

**Q：`启动服务.bat` 显示乱码？**
该文件是 GBK 编码（Windows 批处理要求）。请勿转成 UTF-8，否则脚本会报「不是内部或外部命令」。
从 Releases 下载的包已处理好编码。

**Q：能不能两个平台都克隆后分别推？**
不推荐。请以其中一个为主仓库，另一个用 `git push gitee main` 同步，避免两条历史分叉。
